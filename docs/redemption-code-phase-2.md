# 리딤코드 2차 계획

## 구현 상태

- 공식 이미지 OCR 결과를 확정 코드와 분리된 검수 후보로 저장한다.
- 후보 조회, 인증 import, 승인·거절 API를 제공하고 승인된 후보만 확정 코드로 승격한다.
- `contentHash`, `lastVerifiedAt`, `changeHistory`로 공식 원문 변경을 보존한다.
- 지역, 보상, 만료 정보는 공식 텍스트에서 명시된 값만 병합한다.
- GitHub Actions pull/publish에 후보 데이터를 포함한다.
- 몬길 공식 포럼의 리딤 메뉴는 공식 페이지에서 노출되지만 별도 코드 목록 응답으로 검증되지 않아 기존 공식 게시물 수집을 유지한다.
- HoYoLAB 검색 결과는 공식 작성자를 검증할 수 없는 사용자 게시물이 섞이므로 소스로 등록하지 않는다.
- 비공식 출처는 `SEARCH_ENGINE_URL`의 SearXNG JSON API로 도메인 제한 없이 발견하되, HTTPS 검색 결과의 강하게 표기된 코드만 `web-search-result` 검수 후보로 저장한다.

## 1차 구현 경계

- 허용된 공식 HTTPS 원문의 텍스트에서 명시적으로 식별되는 공용 리딤코드만 저장한다.
- 초대·추천 코드, 구매·개별 지급 쿠폰, 사용자 작성 게시물은 제외한다.
- 이미지나 방송에만 표시된 코드는 OCR이나 음성·영상 추론으로 확정하지 않는다.
- 만료 시각은 공식 원문에 있을 때만 저장하며, 없으면 `null`과 `unknown`을 유지한다.

## 2차 목표

### 1. 공식 텍스트 소스 확대

- 몬길 공식 포럼의 리딤코드 메뉴가 코드 목록인지 입력 화면인지 렌더링 응답으로 판별한다.
- 명조는 허용된 게시판과 `GM 연구소` 작성자 조건을 유지하면서 공용 코드 게시물 탐색 범위를 넓힌다.
- 원신은 공식 콘텐츠 API 외에 공식 작성자를 검증할 수 있는 HoYoLAB 또는 공식 방송 설명문 API가 있는지 조사한다.
- 검색엔진은 공식 후보 URL 발견에만 사용하고 코드 근거로 사용하지 않는다.

### 2. 변경 및 만료 감지

- 공식 원문 정규화 본문의 해시를 저장해 코드 추가, 만료 연장, 삭제 안내를 감지한다.
- 원문에서 사라진 코드만으로 이력을 삭제하지 않고 마지막 확인 시각과 변경 근거를 남긴다.
- 코드별 마지막 확인 시각과 소스별 수집 오류를 공개 수집 상태에 추가한다.

### 3. 보상과 지역 모델 확장

- 공식 원문에서 구조적으로 확인 가능한 경우에만 보상 목록과 지역 제한을 정규화한다.
- 동일 코드가 여러 지역 또는 여러 공식 게시물에 등장할 때의 우선순위와 병합 규칙을 테스트로 고정한다.
- 코드 사용 횟수나 사용자별 사용 상태는 별도 인증 모델 없이는 추가하지 않는다.

### 4. 이미지·방송 후보 검수

- 이미지·방송에만 존재하는 코드는 확정 레코드가 아닌 별도의 검수 후보로 저장한다.
- 후보에는 공식 URL, 발견 시각, 매체 유형만 기록하고 코드 문자열을 임의 추출하지 않는다.
- OCR 또는 영상 처리를 도입하려면 프로젝트 공식 데이터 정책 변경과 사용자 승인을 먼저 받는다.

## 2차 진입 조건

- 1차 deterministic 테스트와 전체 백엔드 검증이 안정적으로 통과한다.
- 게임별 공식 텍스트 코드 사례를 최소 하나 이상 fixture로 확보한다.
- dry-run에서 공용 코드와 제외 대상의 오탐이 없음을 확인한다.
- 운영 데이터 저장 전 동일 조건의 미리보기와 기존 코드 이력 보존을 검증한다.
